# 徽章提示词与界面文本

本目录维护 Badge 8.7 执行链的生成提示词，以及 Badge 界面和复用控件的显示文本。首版为远端 `b4ec184` 的等价迁移：不调整提示词效果，不改变现有交互、默认值、事件时机或控件文案。共享控件仍供旧工作流和 8.8 使用；其他节点的独立提示词不属于本次迁移范围。

## 内容与逻辑边界

| 内容 | 编辑位置 | 职责 |
| --- | --- | --- |
| 控件文案、placeholder、提示、错误与工作流显示默认值 | `ui.zh-CN.json` | 单一文案源，按稳定 key 引用 |
| 文案来源清单 | `ui.sources.json` | 迁移时的源码位置与原文；行号不是后续定位接口 |
| 工作流文案绑定 | `ui.workflow-bindings.json` | 对应仓库分发模板的 JSON 路径 |
| 生成任务 | `prompts/tasks/*.md` | 构建、局部修改、最终配色、Color ID Map |
| 图片角色 | `prompts/references/*.md` | 原稿、高度图、配色图的职责与编号 |
| 保持约束 | `prompts/constraints/*.md` | 颜色、设计、遮罩、材质与光照约束 |
| 摄影表现 | `prompts/photography/*.md` | 构建与棚拍摄影语言 |
| 材质 | `prompts/materials/<id>/*.md` | 六种材质的 surface / avoid |
| 参数句式 | `prompts/fragments/*.md` | 用户补充、强度、例外等可插值文本 |
| 组装顺序与版本 | `prompts/recipes.json` | 有序模板、条件、插槽与 release |

执行节点负责图片、遮罩、参数、阶段、队列和调用顺序。`prompts.py` 保留旧函数接口，将结构化参数映射为配方。`prompt_assembler.py` 只加载、校验、插值和连接文本，不判断图像或修改工作流。

## 组装与追溯

模板变量使用 `{{name}}`。变量必须明确提供，插值只执行一次，用户输入中相同形状的字符不会再次解释。条件只引用代码传入的布尔标记；插槽接收已准备的文本。不在模板里运行代码。未知模板、路径越界或缺少变量会直接报错。

每次实际模型调用在 `badge87_report.prompt_calls` 中记录完整提示词、最终 SHA256、配方版本和各模板哈希。`release` 是内容版本标识；真正重现一次调用应同时保留该条记录和相应 Git 提交。首版使用 `badge87-baseline-v1`，后续提示词更改应更新 release 并单独提交内容变更，可用 Git 比较和回退；目前没有新增版本切换控件。

`prompts/compatibility/uploaded_reference.json` 保存旧版上传配色图的四项措辞替换规则。它也会影响包含相关词语的用户补充，这是旧版行为。第一版保留这一行为，并将规则从程序外置；删除规则应作为独立的行为变更验证。

## 编辑与加载

1. 修改界面文案时，只编辑 `ui.zh-CN.json`，不重编号已有 key。
2. 执行 `python tools/build_badge87_content.py`，生成前端同步模块 `web/badge_ui_catalog.mjs`，同步仓库分发工作流的绑定文案。它不写入用户已保存的工作流或运行状态。
3. 将生成产物一起提交。修改 UI 模块时更新相关 `.mjs` 引用的缓存版本，并重新加载页面；ComfyUI 自动注册的 `.js` 入口保持统一模块 URL，避免重复注册扩展。
4. 调整提示词时修改对应 `.md` 或 `recipes.json`。启用本次 Python 代码重构需要重新启动 ComfyUI；之后 8.7 的模板在组装时读取。兼容导出的 `SURFACES` 是模块载入时快照，使用该接口的调用方需重启后读取更新。

控件中用户可编辑的默认提示词属于 UI 默认值，模型使用的固定约束属于 prompt 文件。已有工作流中用户修改过的文字继续优先保留，不用新默认值覆盖。

## 回归验证

在插件根目录执行：

```text
python tools/build_badge87_content.py --check
node --test tests/*.test.mjs
python -m unittest discover -s tests -p "test_*.py"
```

Python 需使用安装了 ComfyUI 依赖的环境。冻结用例包括 47 组提示词和 19 组完整调用链，覆盖配色图、原稿、纯提示词、局部修改、特殊材质、高度图与 Color ID Map；完整调用链比较提示词、参数、图片/遮罩张量哈希和顺序，不调用付费模型。界面文本基线锁定逐字内容，另校验分发工作流默认值和动态插值。

后续优化影棚光影时，从 `photography/studio.md` 与 `constraints/studio_design.md` 入手，另外检查工作流保存的棚拍用户提示词是否有冲突。效果优化应独立于本次等价迁移提交，并补充实际生成对比。


## 当前摄影版本：badge87-studio-lighting-v3

2026-09-16 增加共用 `photography/studio_lighting.md`，在构建、独立棚拍和非局部最终校色提示词末尾引用。采用左上前方柔光主光、右后方轮廓光、受控金属边缘高光及灰白渐变背景。徽章完整居中，包围盒宽、高各不超过画面对应边长约 45%，至少一项接近 45%；保持宽高比和充分留白。该占比是提示词目标，不是确定性像素约束。

摄影规则明确覆盖旧用户补充中的纯白背景、原图主体占比及逐像素亮度锁定，产品固有色、设计和材质仍受保护。UI 文案、用户保存的文本和局部编辑路径未改动。局部编辑不重新布光或缩放主体。

旧版内容归档在 `tests/fixtures/badge87_content_baseline.json`，原有 47 组提示词及 19 组调用链继续使用归档版本验证。新版额外验证 19 组调用中仅授权的摄影提示词变化，图片、遮罩、参数、调用顺序及局部提示词保持一致。没有实际出图验收，需对比生成结果确认视觉效果。
