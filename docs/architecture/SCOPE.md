# 本轮改造范围（后续阶段共同遵守）

依据用户最新确认：只调整已经实现的创作画布模式及其相关节点。本文优先于第一、二阶段文档中可能被理解为全工程迁移的表述。

## 纳入

- 创作画布入口、容器、卡片、交互和视图持久化。
- 当前已接入创作画布的多维表格/分镜、Prompt、LibTV 生成与批处理、素材预览，以及 DAELab 对 ComfyTV 的兼容路径。
- 为上述功能建立的共享组件、独立陈列和宿主适配。消费方必须登记为创作画布范围内，不能因共用控件名称自动纳入其他节点。

## 排除

- 展厅、徽章阶段基于 App Mode 的节点、界面、样式和交互，不做迁移、重设计或顺带清理。
- 其他未接入当前创作画布的节点，不扩展迁移范围。
- ComfyTV 上游代码继续只读。

## 共享代码与验收边界

1. 旧共享控件可作为复用来源，但不能为了创作画布直接改变展厅/徽章所使用的默认样式、默认行为或公共接口。优先复用纯逻辑，使用创作画布专属组件入口和作用域；必要时新增显式可选配置，保留旧调用方行为。
2. 不修改展厅/徽章调用点，不把旧 App Mode 强制接入新组件。若无法隔离影响，保留旧实现，并把更大范围重构列为未纳入事项。
3. “改一处、多处生效”仅指已登记的创作画布组件实例与独立陈列。旧 App Mode 实例不应跟随新主题或新交互变化。
4. Graph/App Mode 的检查仅是切出创作画布、恢复面板及原行为的不回归检查，不是重构交付。已有非 Active/Bypass 约束继续保留，不重写展厅/徽章实现。
5. 仅调整实现创作画布目标必要的数据接口；第一阶段发现的后端耦合不自动授权独立的全局后端重构。
6. 后续每项变更记录消费方与影响面。若触及共用底层，补针对旧调用方式的不回归验证；新 CSS 不得以全局选择器覆盖旧 App Mode。

本次是计划范围澄清，仅修改文档。此前第一、二阶段也没有迁移运行代码。

## 后续样式基准修订

用户确认独立环境与现有创作画布样式不一致后，采用 [ComfyUI 原生 JSON 陈列](native-gallery/README.md)作为主要视觉/交互验收入口。独立环境仅保留为辅助组件测试工具；其新主题不直接迁入产品。先依据原生陈列提取共享样式，再进行必要的组件接入。
