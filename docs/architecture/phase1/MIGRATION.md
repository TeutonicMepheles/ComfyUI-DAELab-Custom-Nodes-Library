# 分阶段迁移与验收

> 范围以[本轮改造范围](../SCOPE.md)为准：仅现有创作画布及相关节点；展厅、徽章 App Mode 不调整。

每阶段交付一个可复核结果；保留旧路径直到替代路径通过对应验收。本轮仅完成第一阶段文档，不代表后续实现已获测试通过。

## 推进顺序

| 阶段 | 具体交付 | 通过条件 |
| --- | --- | --- |
| 1 现状与边界 | 本目录文档、依赖账本、数据归属、保留清单、共享组件与实例更新契约 | 源码证据可定位、内部链接有效、已有运行文件内容不变；明确共享实现与实例数据的边界、更新范围和兼容规则 |
| 2 最小规范与组件契约 | 实际样式盘点；设计变量；首批组件目录、参数/事件/变体/覆盖规则；交互规范；图标目录 | 覆盖默认、悬停、焦点、禁用、忙碌、失败；键盘/拖动冲突和空状态有定义；每项映射唯一拟定实现及消费方，并有同步更新验收用例 |
| 3 独立陈列 | 同仓库独立启动页；首批真实控件；模拟成功/失败/延迟状态 | 停止 ComfyUI 后可启动；展示与产品共用源码；控件没有宿主导入；能实际操作和切换状态 |
| 4 宿主适配 | HostAdapter、生命周期/旧面板适配、真实 ComfyUI 集成页 | 创作画布刷新、重开、节点删除无重复挂载或残留订阅；切出到 Graph/App Mode 保持旧行为，展厅/徽章不迁移 |
| 5 单条真实链路 | 创作画布设置→LibTV 生成→视频预览→ComfyTV 抽帧 | 真实视频可播放，真实输出帧可见；请求身份与恢复有效；本地模拟、已有任务恢复、真实付费调用分别记录证据 |
| 6 表格和批处理 | 完整导入→映射→解析→编辑→复核→生成→结果回写 | 通用表格与分镜均通过；迟到响应不覆盖；重排/删除不串行；恢复不重复提交；不能只交付共享编辑器 |
| 7 协作约束 | 自动依赖检查、规范化任务模板、旧路径清理 | UI 和一个功能可分别修改并集成；禁止依赖有自动失败证据；兼容例外关闭或有明确剩余期限/触发条件 |

第三阶段只做够支持一条纵向链路的组件：按钮、参数输入、弹层/浮层、媒体预览、生成状态、卡片容器。表格复杂编辑可暂留兼容层，避免先做一个庞大却未被产品使用的控件库。

## 第二阶段执行补充

第二阶段仍是规范和组件契约交付，不提前大规模迁移产品。需要产出以下可核对内容：

1. 首批组件登记表：组件名称、现有可复用实现、唯一拟定源码入口、维护模块、陈列案例、产品消费入口，以及未迁移状态。
2. 设计变量表：统一命名、取值和使用范围；说明哪些是全局主题变量、哪些是明确允许的实例配置。
3. 组件契约：参数、事件、插槽/组合、允许变体、状态与交互；实例数据的拥有者；不允许外部覆盖的核心行为。
4. 更新与兼容规则：区分纯视觉/行为修改、默认值修改、契约破坏、持久化格式修改；分别列出消费方复核或迁移要求。
5. 同步更新验收脚本：按下节准备操作、预期和证据位置。此阶段仅完成用例设计，不能把用例标记为已通过。

验收者应能从任一首批控件追踪到唯一拟定实现、至少一个消费方和一个更新测试；只有效果图或视觉文字描述不能通过第二阶段验收。

## “改一处、多处生效”必测用例

- 第三阶段：在独立陈列中创建两个数据不同的同组件实例，只改共享源码的一项样式和一项通用行为，重新加载后两者同步变化；编辑其中一个实例的数据不改变另一个。
- 第四阶段：同一组件同时出现在陈列与两个真实节点中，重复上述修改；三个入口均更新，消费方文件无需逐一修改。检查实际引用和资源版本，排除复制实现或样式覆盖造成的假同步。
- 保存并重开已有工作流，实例参数和素材保持原值；未设置的新默认值按契约生效。保留节点切换、销毁和恢复验证。
- 记录改动前后效果、实际操作结果和引用路径；验收用的临时改动结束后撤回或明确纳入产品，不能遗留调试外观。

第三阶段通过只证明独立环境内成立，第四阶段通过才证明真实 ComfyUI 接入成立；创作画布范围内的覆盖随第六、七阶段迁移清单逐项确认。

## 必须保留的行为

下列测试为当前已有候选证据，第一阶段没有重新执行它们。实施时先核对测试内容，再补新增边界测试；测试通过不能替代浏览器实操。

| 能力 | 必须保留 | 已有验证入口 / 后续实操 |
| --- | --- | --- |
| 表格与文档导入 | 稳定字段/行/素材身份；原文保留；覆盖前确认；编辑与撤销；旧格式 | `tests/data_table.test.mjs`、`tests/test_data_table.py`、`tests/test_daelab_storyboard_import.py`；导入后编辑/保存/重开 |
| Prompt 与引用 | 结构化 ref；被排除素材不提交；迟到解析不覆盖手改；revision 不随撤销回退 | `tests/table_prompt.test.mjs`、`tests/table_video_references.test.mjs`、`tests/test_prompt_compiler.py`；慢请求时编辑、撤销、换工作流 |
| 任务恢复 | 同请求同输入恢复；同请求不同输入拒绝；不可变媒体快照；按原行回写 | `tests/test_libtv_batch.py`、`tools/storyboard_batch_smoke.cjs`；中断/刷新后核对任务且不新建远端生成 |
| 创作画布 | 菜单入口、布局和视口持久化；表格/媒体/连接可用；原图数据保留 | `tests/creative_canvas_model.test.mjs`、`tools/creative_canvas_smoke.cjs`；拖动、缩放、刷新、切模式 |
| App Mode | Bypassed/Muted 等非 Active 收起，恢复 Active 还原 | `tests/app_mode_bypass_model.test.mjs` 与共享实现；每个迁移节点真实切换 |
| 视频及 ComfyTV | 合法本地输出、可播放、结果去重、抽帧可见；插件缺失有降级 | `web/libtv_canvas_result.mjs`、`tools/libtv_saved_result_smoke.cjs`；实际加载视频及执行抽帧 |
| 控件生命周期 | 关闭弹层/删除节点/切换文档后没有旧回调写入 | 第四阶段补可控延迟、重复挂载/释放测试；浏览器检查焦点与媒体停止 |

不得把一次成功截图当成刷新恢复或跨工作流隔离的证明。真实外部调用只在对应验收范围和可用模型明确后执行，不能拿模拟结果冒充真实服务验证。

## 依赖账本退出顺序

1. 第二、三阶段处理 D07、D04：统一最小控件与容器，不触碰生成身份。
2. 第四阶段隔离 D01、D06、D09：先包裹旧实现，测试双重挂载、失效菜单和上游插件缺失。
3. 第五阶段建立 GenerationPort 和应用编排，验证单条链路。D08 先定义契约，提取必须保持 Python 行为等价。
4. 第六阶段处理 D02、D03、D05：表格交互与生成流程拆分、文档单一写入口、明确设置覆盖。D08 的通用化随批处理迁移完成。
5. 第七阶段删除已无调用的兼容代码。不能仅将代码移入名为 adapter 的文件便关闭问题项。

## 跨 Session 协作方式

每个实施任务引用本目录，并写明：本次所属阶段、允许修改模块、使用的公共接口、保持的不变量、验收入口、未解决例外。共享接口变化先同步到设计文档和契约测试；功能内部变更不要求其他功能跟着改。

角色按边界分工：设计/控件负责人管理 design/ui；功能负责人管理 feature；集成负责人管理 application/adapters；后端负责人管理任务与媒体。角色不要求对应固定的人，也不要求新增线程或子代理。

每次交付记录：改动内容、可运行入口、实际验证与结果、未验证项、回退方式。保留旧序列化读取器到已有工作流迁移验收完成；切换新入口应可回退，不能靠删除用户数据恢复。

## 本轮核验范围

`verification.json` 记录当前分支/HEAD、前端入口数量、文档链接检查及本轮基线文件哈希核对结果。基线包含 web/nodes/tests/tools 下已有文件，排除 Python 缓存；它只证明本轮核验范围内文件内容没有变化，不证明整个工作目录没有其他任务修改，也不证明既有代码无缺陷。
