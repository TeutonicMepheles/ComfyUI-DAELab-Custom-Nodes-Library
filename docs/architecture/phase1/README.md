## 主要结论

- 控件陈列环境采用**同仓库、独立启动、复用同一份控件源码**。另设 ComfyUI 内的集成验收入口。独立陈列验证控件；集成入口验证真实宿主行为。
- 共享组件必须支持“改一处、多处生效”，同时保持实例数据独立。已补充组件更新、变体、覆盖及兼容约束；第三、四阶段分别提供独立环境和真实宿主的同步更新证据。
- 现有通用表格、Prompt 状态保护、任务恢复、媒体快照应继续复用。不能为了换成 Vue 而重写这些业务规则。
- 优先处理跨模块私有字段、数据双向同步、面板搬运和宿主访问。移动文件并不等于解耦。
- 创作画布负责布局和操作入口；表格负责内容；生成服务负责任务；宿主适配器负责 ComfyUI。跨功能流程由应用层协调。
- ComfyTV 上游保持只读。适配器只能使用其公开能力和已注册节点；DAELab 实现仍位于本仓库。

## 用 Unity 经验理解边界

| 前端概念 | 可类比的 Unity 经验 |
| --- | --- |
| 设计变量和基础控件 | 统一皮肤、样式资源和通用 UI Prefab |
| 独立控件陈列 | 不加载完整游戏的 UI 测试场景 |
| 功能模块 | 自己管理状态、通过接口协作的功能系统 |
| 宿主适配器 | 隔离平台 API、场景对象和生命周期的桥接层 |
| 应用编排 | 协调多个系统完成一次用户操作的流程控制器 |

这是帮助理解的类比，不表示浏览器组件生命周期与 Unity 完全相同。
