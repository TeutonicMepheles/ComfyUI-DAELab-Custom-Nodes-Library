## 一、已确认目标与边界

- 沿用现有原生 DOM、主题与控件体系，不引入 shadcn 或 React。
- 展厅参照徽章统一模型选择、参数分区、折叠和生成区；抽取两者实际共同消费的生成配置面板。
- 徽章、展厅初次生成的每批图片数量均限制为整数 1–4，默认 1；UI 统一使用“张数／张”。它表示徽章 build 的 count 或展厅整体生成节点的 n，不表示队列重复次数、HTTP 请求数或固定积分。旧初次生成配置中的合法整数 5–8 恢复为 4，并提示一次，下次保存写入新值，不自动生成。其他阶段的既有数量语义保持。

- 1118 局部修改 L1–L7 不纳入本次实施，仅预留阶段接口；现有局部修改继续可用。不新增模型、不承诺未接入的模型能力。
- 任务来源：[AIGC 工具链 1113 会议与 1118 修改交付](https://golajahfarm.feishu.cn/docx/TB4pdmD4boNSVxxOdk2cTc18ndg)，2026-11-18 复审已通过 lark-cli 只读核对其“展厅 UI 统一”和公共回归要求。应用两边及旧配置恢复策略沿用本计划已记录的约定；源文档没有单独规定迁移算法。统一模型配置、1118 局部修改、抠图整合是其他主线，不作为本任务新增功能。

## 三、具体修改方案

### 业务共享层

- 新增 `web/generation_config_panel.mjs`，从徽章实现抽取通用DOM视图；旧 `badge_generation_panel.mjs` 保留包装接口，降低旧调用方改动。
- 面板接收 `instanceId`、stage、能力描述、配置快照、`onChange(next)`、`onGenerate()` 与展示状态；返回 `element/update/dispose`。通用层不接收 graph、不查节点编号、不发请求。徽章包装层继续提供现有调用方消费的 `button/status/modelControl/setPresets/update/dispose`，尤其保留 local 的外置模型控件及状态反馈，不只保留函数名。
- 参数能力描述包含每个模型的可见字段、固定预设、auto、Custom、宽高范围/步长/业务校验、quality、数量范围和继承/禁用原因。只显示该业务有映射的字段；徽章不因展厅有quality而新增未接线控件。展厅保留auto与当前尺寸，不默认改成徽章1:1/1K，也不删去已有4K选项。模型能力变化后由业务适配器重新核对参数；不把徽章比例、像素总数或16倍数规则硬编码进通用层。
- 每实例独立DOM、草稿、焦点ID和监听；ID使用运行时 graph 实例、工作流加载epoch与本次挂载身份，不能仅拼工作流UUID或stage，因为复制文件可能保留相同UUID。加载/重载时必须释放旧实例并递增加载身份，包括同一LGraph对象被configure重用的情况。释放需取消事件、拖拽绑定、订阅及观察器，移除外置 `modelControl`，旧异步回调不可更新新实例。
- `onGenerate` 必须返回实际提交Promise，去掉旧 `void onGenerate()` 包装。共享按钮只管理此次Promise的临时忙碌态；业务现有执行会话负责排队后直到完成/失败的busy，通过update提供给视图。进入回调前同步锁定，避免双击或Enter重复入队；成功/失败均恢复可重试状态，避免叠加两套互相覆盖的disabled管理。
- 对控件复用的评估入口包括 `badge_generation_panel.mjs`、`gpt_image2_config_panel.mjs`、`table_generation_panel.mjs`、`compact_color_group_controls.mjs`、`dynamic_widget_lifecycle.mjs` 及 Canvas 的按钮／字段。前者提供主视图，GPT配置模块提供输入去重思路，表格面板用于核对已有能力表达；不引入表格任务/模型服务依赖。数字拖拽继续复用已有绑定并补释放出口，避免另写手势。
