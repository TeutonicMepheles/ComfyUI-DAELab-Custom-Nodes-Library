# 剧本到生成任务的持续连线

`DAELAB.ScriptParser.table_json → DAELAB.Table.source_table → DAELAB.LLMStylePreviewB.多维表格 → 逐行结果 → DAELAB.LibTV.VideoGenerate.table_json`。

表格新增可选 `source_table` 输入，已有槽位保持原序。连接后显示上游全部记录，以现有行复选框选择要送入 LLM 的镜头。字段通过稳定 ID 映射，正文与图片由上游维护；已保存表格只是缓存，不代替连线。断线、停用、循环、字段删除均阻止下游继续消费。未连接的普通表格保持原有行为。

LLM 的处理要求、模式和模型继续参与审批签名。沿用现有“生成”和“同意更改”：前者调用所选模型，后者才发布输出。新增槽位 1“逐行结果”保留镜头 ID、优化文本和参考图；槽位 0 继续输出合并文字。已连接逐行结果时应用会直接更新下游，不额外创建文本框。原生执行只读取审批缓存，不调用模型。

生成面板经公开 `inputSnapshot` 接口消费逐行数据，独立安装时使用业务包公开读取函数。以镜头 ID 同步任务，保留模型配置、历史回执与视频；取消选择的任务放入序列化 `archivedTasks`，重新选择后恢复。输入变化或撤销应用时显示原结果但禁止生成；点击生成前再次检查输入，避免轮询间隔内消费旧审批。同步过程不提交、重试或恢复任何生成请求。

复用现有表格复选框、LLM 工作台、提示词编辑器、首帧绑定和生成任务面板。没有增加样式或替换共享画布行为。生成节点保留历史类型名，但此链路没有使用 `ComfyTV.*` / `DAELAB.ComfyTV.*` 节点。

回归入口：`node --test tests/live_chain.test.mjs tests/llm_slot_model.test.mjs`。实际 ComfyUI 检查需覆盖两张选行表、修改解析源、审批失效/恢复、任务结果保留、保存重载和播放；不得为了验收提交付费生成。

单镜头比较多种生成方式时，同一 LLM 的槽位 0「结果」可以分别连接生成节点的 `text_input`，上传节点分别连接 `first_frame`、`last_frame` 或 `reference_video`。这条路径消费已经应用的优化结果；输入失效时阻止生成，不需导出表格。文生视频分支不连接生成参考素材，提示词优化阶段仍可读取剧本中的参考图。

文字同步保留提示词中的首尾帧和素材引用；参考素材输入按当前素材 ID 更新绑定，避免更换视频后残留旧 ID。视频参考自动进入 `mixed2video`，图片参考进入 `image2video`，最终仍由具体模型能力校验。回归入口：`node --test tests/video_task_linked_prompt.test.mjs`。
