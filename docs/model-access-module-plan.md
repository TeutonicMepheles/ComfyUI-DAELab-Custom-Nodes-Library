# CNL 通用模型接入模块执行计划

**待实施**

## 目标与首批范围

在 CNL 建立工作流可复用的模型接入模块。已有执行适配器能够处理的新模型，通过登记配置即可进入兼容工作流的候选列表。用户选择后，工作流能够编译出正确参数，服务端能够校验并路由到对应执行器，保存重开后能够恢复原选择。

徽章与展厅是首批接入的工作流。首批正式上线模型为 `gpt-image-2`、`gpt-image-2.5-flare`、`gpt-image-2.5-sunburst`。通用合同覆盖图片、视频、文本等任务声明，新增生产模型、Studio 目录迁移及 3D 执行适配留待后续。首批沿用已有工作流的生成、编辑和抠图入口。

## 2. 模型目录与配置接入

CNL 随包维护一个版本化模型目录，每款模型使用独立的配置条目。首版在启动时读取目录，增改配置后重启生效。交付配置结构说明和可照用的样例，列出必要字段、默认值及校验错误。

| 配置内容 | 约定 |
| --- | --- |
| 模型标识 | 稳定 ID、显示名、提供方模型名及必要的旧值别名。显示名和提供方名称变更时，通过稳定 ID 和别名恢复旧工作流。 |
| 模型能力 | 任务类型、语义化输入输出及其类型、参数类型、范围、枚举、默认值和约束。模型声明实际可用能力，例如参考图输入、批内张数和质量档位。 |
| 执行信息 | 注册的执行适配器 ID、执行路由、输入参数和输出映射。适配器已支持的模型通过配置映射接入。新协议、新端口结构或新执行方式通过可复用适配器接入。 |
| 环境依据 | 开放属性及其来源、运行位置和环境要求。凭据继续由现有宿主管理。 |

目录加载时检查版本、ID 和别名唯一性、参数定义及映射完整性。条目缺少执行适配器、宿主缺少必要能力或条目不可用时，由服务端给出原因并过滤该模型。配置仅引用已注册的执行方式。稳定 ID 或旧值无法解析时，保留保存值并禁用对应生成。

## 3. 工作流能力声明与执行适配

工作流按阶段登记能力声明，包括任务类型、输入输出、执行方式、必要参数及业务限制。候选由模型目录、已注册适配器、宿主能力、环境策略和阶段声明求交集。工作流可通过同一合同使用当前及后续型号。节点编号、工作流标记、历史字段和编译规则放在消费方适配器中。

在首批用现有 `OpenAIGPTImageNodeV2` 验证配置接入。若另一款图片模型需要不同节点或不同端口，工作流只有在存在对应执行映射时才将其列为候选。例如展厅初次生成要求图片输出、参考图输入、尺寸及质量控制，且最多每批四张。模型或宿主的数量上限更低时，采用更严格的范围。

前后端消费同一份已注册的能力声明。提供只读 `GET /daelab/cnl/model-access`，返回目录版本、环境状态、指定消费方和阶段的有效能力及可供界面展示的不可用原因。服务端完成宿主节点注册与禁用处理后再解析能力。提交时从识别到的工作流与阶段选取服务端规则，校验实际执行图和映射后的参数。

## 4. 宿主环境与提交校验

### 宿主环境

通过 `folder_paths.get_user_directory()` 定位 `daelab/model-access.json`，启动时读取版本与 `internal`／`external` 设置。仅在文件确实缺失时使用 `external`。文件不可读、格式非法或版本未知时，受管生成入口显示原因并禁用，编辑、保存和可用的本地操作继续运行。

`internal` 仅允许开放属性有依据且满足内网条件的模型。路由与开放属性分别判定。`external` 允许满足运行条件的开放和闭源模型。当前三款使用外部 API，内网环境显示无可用模型，保留原选项与参数。这里的环境策略作用于接入模块的消费方。

### 提交边界

CNL 注册一次适用于 `POST /prompt` 与 `POST /api/prompt` 的校验。徽章执行器按节点类型识别，展厅以提交中携带的 `daelabExhibitionUiV1` 识别工作流，再判断哪些生成节点进入本次执行路径。识别业务归属后再检查目录资格，目录外型号也受规则约束。带损坏或未知版本标记的展厅生成请求返回结构化错误。无标记的原生图按宿主规则处理。

业务按钮、原生运行与受识别的直接请求使用同一规则。入队前可判定的失败返回宿主可展示的 `error` 和 `node_errors`，队列无新增。对目标宿主核验最终入队图。若宿主的 prompt handler 或节点替换在校验后仍能改变受管节点或参数，先接入该宿主可用的最终校验点，再认定支持。集成通过 CNL 完成，沿用宿主的现有认证通道。

## 5. 首批工作流集成与兼容

| 路径 | 接入要求 |
| --- | --- |
| 徽章 87／88 | 复用现有执行链，覆盖 `BadgeApp87V1`、旧 `BadgeApp88V1` 和当前 `BadgeApp88TargetOnlyV1`。执行适配后校验实际调用的模型，包括旧 88 区域材质固定使用的 `gpt-image-2`。覆盖应用、颜色收尾与旧版 Color ID Map 缓存未命中的外部调用。本地预览及缓存命中可用。 |
| 展厅初次生成 `1040` | 复用原生节点。校验模型、尺寸、质量、批内张数及编译后的参考图来源和顺序。 |
| 展厅后续生成 `1035`、`1058` | 按本次执行路径校验，覆盖 `1035` 从 Bypass 恢复 Active。保留各自的数量规则及连线。使用 `auto` 时宽高连线不参与尺寸校验。使用 `Custom` 时，入队前校验字面量、可静态解析的宽高和已知动态来源。现有 `GetImageSize+` 连线由原生节点在调用 API 前校验算出的实际值。无法确认来源的 `Custom` 连线在入队前拒绝。 |
| 现有独立图像编辑 | 对受管工作流提交的外部图像调用执行环境和模型授权，沿用编辑器既有参数与数量规则。本地抠图继续独立运行。 |

徽章和展厅初次生成均为每批整数 1–4 张，沿用单次提交及原有批内语义。徽章保留尺寸预设，例如 `1536×864` 映射为 `Custom`。展厅保留各模型支持的自动尺寸、4K、自定义尺寸和质量档位。后续阶段沿用各自数量规则。

复用 `createGenerationConfigPanel`、现有折叠、历史、实例隔离和数量迁移。保留节点类型、widget 索引、连线和业务元数据。在隔离副本中验证保存和重载。旧模型及参数照原值打开，遇到不可用值时显示原因。只有用户主动切换时才对不兼容字段采用目标模型的有效默认值，并标明调整项。

## 6. 验收与发布

| 验收项 | 通过标准 |
| --- | --- |
| 只改配置即可接入 | 在隔离环境仅增加一条模型配置，使用已注册的执行适配器。兼容工作流自动出现候选，选择后正确编译、通过服务端校验并到达替身执行，保存重开后恢复。不兼容工作流过滤该型号。 |
| 模块独立性 | 第三个测试消费方经同一注册和查询接口声明能力、获取候选并编译。使用非图片任务与另一种执行适配器的夹具，验证通用层可解析、校验与分发。 |
| 目录与环境 | 覆盖宿主缺模型、缺字段、查询失败、未注册适配器，以及目录外型号。覆盖缺配置、内网、外网、非法配置与重启生效。验证无候选时仍可编辑和保存。 |
| 服务端与编译图 | 在实际隔离 ComfyUI 中测试两个 POST 路由、业务按钮、原生运行和直接提交。覆盖有效、损坏、未知版本及缺失标记。拒绝时队列无新增，允许时仅入队一次且保留原连线。 |
| 阶段与兼容 | 覆盖徽章各执行器的实际型号、本地预览与缓存、初次生成 1–4 边界和旧值迁移。覆盖展厅 `1035` 启用、`1058` 动态宽高、`1040`／`1058` 参考图来源、4K 与模型质量切换。 |
| 实际 UI 与安装 | 检查双实例、焦点与溢出、折叠、Active／Bypass／Mute、App Mode 切换、保存重开和相关视口／缩放。验证 CNL 独立、配 Canvas、配 Studio 与三包组合，检查注册唯一及跨包依赖。 |

自动测试使用目录、宿主和执行器夹具。实际宿主测试以替身执行或禁用外部传输。验收结论覆盖编译、校验和排队行为，真实模型效果、代理调用次数和扣费留待独立验证。

交付通用模块及接口、配置结构及样例、两个消费方适配、测试与实际 UI 记录，以及匹配的更新包、回滚包和版本清单。发布清单注明恢复旧版后的环境策略状态。**全部验收项通过后，更新飞书「模块一 模型接入」的完成状态及技术总结。**
