# 自有 DeepSeek API 可选接入

2026-10-08，用户明确要求“为了先推功能，先给我一个走自己 Deepseek API 的可选项”。本增量在现有优化流程增加提供方选择，不替换 ComfyUI Partner，也不将此前未通过的 M6 标记为通过。首先交付可配置、可验证的接入；真实 DeepSeek 文本效果和账户账单需使用用户自己的密钥另行实测。

## 使用方式

在单元格或整列的“优化提示词”侧栏选择“自有 DeepSeek API”，选择模型，在密码输入框设置本页使用的 API Key，再更新估算并开始优化。密钥只在当前页面内存中保存，关闭或刷新页面后需重新输入，不保存到工作流、浏览器存储或优化账本。也可在启动 ComfyUI 的进程环境中配置 `DEEPSEEK_API_KEY`；页面只能看到是否配置，不能读取该值。

选择自有 DeepSeek 时默认模型为 `deepseek-flash`；按用户 2026-10-09 指示，后续验收只使用 Flash。保留 `deepseek-v4-pro` 作为手动可选模型，不自动升级。使用官方固定地址 `https://api.deepseek.com/chat/completions`。以 system 消息发送固定优化规则，以 user 消息发送冻结输入，关闭思考模式，单次最大输出沿用 1024 tokens。仍然只发送可编辑文字与只读文字上下文，不上传图片、视频或素材路径。

## 行为与兼容

DeepSeek 和 Comfy Partner 共用同一面板、控制器、状态显示和应用事务。当前选择 DeepSeek 只是替换模型产出通道，不建立另一套 UI 流程；公共交互修复同时作用于两者，公共交互验收也统一记录。只有密钥/账号鉴权、模型与费用信息、服务真实支持的远端查询能力需要适配。

- 复用原有选择、范围冻结、引用保护、建议预览、手动应用、撤销重做及服务端串行提交。结果不会自动覆盖原提示词。
- 模型决定提供方；服务端以账本中冻结模型核对，不能由页面当前选择改变已有批次的路由。切换提供方或模型使估算失效。旧 Comfy 批次仍保留原模型与积分单位。
- DeepSeek 与 Comfy 凭据严格分开。自有密钥通过专用临时请求头传到本机服务，再由服务端直连 DeepSeek；不经过 Comfy Partner。
- POST 不重试、不静默切换模型。缺少密钥时在提交前报错；连接中断或响应丢失时记为 unknown，需要用户明确新建请求。
- DeepSeek Chat Completions 无本实现可用的远端结果查询接口。已完成结果从本地账本恢复；遗失的响应不能根据 ID 再取回，也不能发到 Comfy 的查询接口。

## 费用显示

Comfy 保持积分显示。DeepSeek 单独显示 USD，费用由 DeepSeek 账户承担。内部兼容字段 `estimatedCredits` / `budgetUpperCredits` 的单位必须读取 `price.currency`，不能按字段名将 DeepSeek 数值称为积分，也不能跨币种汇总。

费率来源：[DeepSeek 官方价格](https://api-docs.deepseek.com/quick_start/pricing/)，核对日期 2026-10-08。采用峰值、未命中缓存的保守参考费率：Flash 输入 0.30 / 输出 1.20 USD 每百万 tokens；Pro 输入 1.32 / 输出 3.96 USD 每百万 tokens。预计输入仍使用 UTF-8 字节保守计数；报价为计算估算，不是锁定账单价格。官方费率可能调整。

返回的 token usage 与按上述费率计算的用量费用仅作为估算。不得将其标为实际扣款，也不得将缺失账单显示为零。原 Comfy 未知提交与费用记录保持不变。
