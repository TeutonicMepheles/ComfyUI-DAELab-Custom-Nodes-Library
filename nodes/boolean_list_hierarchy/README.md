# Boolean List Hierarchy

## 节点信息

- 节点 ID：`BooleanListHierarchy`
- 显示名称：`Boolean List Hierarchy`
- 分类：`utils/logic`

## 功能

`Boolean List Hierarchy` 在一个节点内维护最多 64 个动态布尔输出，并支持最多三层结构（Root → 子项 → 孙项）、祖先级联、同层互斥组和跨分支依赖：

- 任一祖先为 `false` 时，其所有后代立即变为 `false`，且后代布尔开关被禁用。
- 祖先恢复为 `true` 后，后代开关恢复可用，但不会恢复关闭前的值。
- 子项和孙项不会反向修改祖先。
- 同一个直接父项下的两个或多个兄弟条目可以加入互斥组；所有根项视为共享一个隐式 Root。
- 每个互斥组最多一个条目为 `true`，但允许全部为 `false`。开启一个成员会立即关闭组内其他成员。
- 一个条目可以依赖当前节点内任意多个其他条目。开启依赖者会递归开启全部前置项及其祖先；关闭前置项会递归关闭所有依赖者。
- 每个条目使用稳定 ID；层级编辑或排序后，已有输出连线仍跟随原条目。

## 输入与输出

- `config_json`：隐藏的内部配置输入，由前端编辑器维护并随工作流序列化；通常无需手动修改。
- `Boolean 1` 至 `Boolean 64`：固定后端输出槽。当前可见条目按界面顺序映射到前 N 个输出，其余输出为 `false`。

条目名称只影响显示，不影响稳定 ID。重命名、同级移动、缩进或提升条目时，前端会按稳定 ID 重排连接，避免连线错绑到其他布尔项。

条目配置使用 `{id, label, value, parent_id}`，加入互斥组的条目额外保存可选字段 `exclusive_group_id`，存在跨分支依赖时保存 `requires_ids` 稳定 ID 数组。每个条目最多属于一个互斥组。

## 行级 ICON

- 新增子项
- 同级上移、下移
- 缩进到前一个同级条目；若移动后的子树会超过三层则禁用
- 将子项或孙项提升一级
- 删除条目；存在后代时级联删除整棵子树

工具栏提供新增根项、`Exclusive groups` 和 `Dependencies` 管理面板。节点始终至少保留一个根项，达到 64 项后停止新增。

祖先关闭时只禁用后代的布尔开关；名称编辑、排序、提升和删除仍可使用。

## 使用步骤

1. 点击工具栏新增根项，或点击根项/一级子项的“新增子项”图标。
2. 编辑条目名称并设置布尔值。
3. 使用上移、下移、缩进和提升图标组织最多三层关系。
4. 从对应输出连接需要接收布尔值的节点；后续重排不会改变条目的稳定绑定。

父项从 `true` 变为 `false` 时，其所有后代会递归写为 `false`。父项重新开启后，后代只恢复可编辑状态，不恢复关闭前的旧值。

## 互斥组

1. 打开工具栏中的 `Exclusive groups` 面板，点击 `New group`。
2. 选择根层或某个父项的子项层，并勾选至少两个条目。
3. 点击 `Save`。组成员行会显示 `EX` 标记，悬停可查看同组成员。
4. 在面板中可编辑成员或删除互斥组。删除组只解除关系，不改变当前布尔值。

条目只能与同一直接父项下的兄弟成组。已属于其他组的条目在选择器中不可选。若建组前多个成员为 `true`，保存时保留界面顺序中的第一个；此后主动开启任意成员时，该成员优先，其余成员自动关闭。

互斥约束先于祖先级联执行。因此一个条目因互斥关系被关闭时，它的所有后代也会被递归写为 `false`。关闭当前唯一开启的组成员不会自动开启其他成员。

同级排序和重命名保留组关系。移动父项会携带完整子树；缩进或提升会先把被移动条目移出原组，后代的同父互斥关系保持不变。删除成员后若组内不足两个条目，该组自动解散。

## 跨分支依赖

1. 打开 `Dependencies` 面板并点击 `New dependency`。
2. 选择依赖者，再从整个 Hierarchy 中勾选一个或多个前置条目。
3. 点击 `Save`。依赖者行显示 `REQ` 标记，面板按 `依赖者 ← 前置项 A + 前置项 B` 展示规则。
4. 开启依赖者时，所有前置项、传递前置项及它们的父级祖先会自动开启。

多个前置项使用 AND 关系。若自动开启的前置项位于互斥组，它会关闭该组原先开启的成员；受影响成员的后代和依赖者随后递归关闭。编辑器会阻止自引用、循环、依赖自身后代，以及同一个启用闭包中同时要求两个互斥成员的配置。

依赖关系使用稳定 ID，因此重命名和排序不会破坏绑定。删除前置条目会自动清除其他条目中对它的引用。父子关系仍负责界面层级和子项禁用；`requires_ids` 只表达同一节点内的额外前置条件。

## 兼容性

旧版 `{label, value, level}` 配置会在加载时迁移为 `{id, label, value, parent_id}`。缺少 `exclusive_group_id` 或 `requires_ids` 时分别按未分组、无额外依赖处理。孤立条目、循环关系、无效父项或超过三层的条目会确定性地提升为根项；非法互斥组和依赖边会被确定性清理。节点 ID、`boolean_list_items` 属性名和最多 64 个后端输出保持不变。

较新的工作流通过隐藏的 `config_json` 传递当前界面状态；没有该输入的旧工作流仍会从 `properties.boolean_list_items` 恢复配置。
