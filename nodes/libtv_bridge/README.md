# LibTV Video Bridge

Node: `DAELAB.LibTV.VideoGenerate` / **LibTV Video Bridge / 视频互传**.

This node uses the official `libtv` executable and its existing local login. It spends
LibTV credits, never Comfy credits. It imports no ComfyTV code.

## Usage

1. Install/login with the official LibTV CLI (`libtv login web --open`).
2. Create a LibTV canvas and copy its UUID into `project_uuid`.
3. Choose a model and mode. For text-only tests choose `text2video`.
4. Seedance smoke defaults: 4 seconds, 480p, 16:9, sound off.
   Minimax H3: 5 seconds, **768P**, 16:9, sound off. H3 does not expose a sound toggle.
5. For first/last-frame generation connect `first_frame` and optionally `last_frame`.
   Each accepts exactly one IMAGE. Additional images use `reference_images`.
6. `reference_files` accepts a JSON array of local input/output/temp file paths or
   Comfy `/view` URLs (image, video, audio). `reference_video` accepts a compatible
   `COMFYTV_VIDEO` local URL. Input order is first frame, last frame, image batch,
   file list, then reference video. Mixed references use `mixed2video`.
   Prompts may reference `@image_1`, `@video_1`, `@audio_1`, etc.; numbering is
   one-based within each media type and is translated to LibTV node references.
7. Run. The node previews the downloaded video and returns native `VIDEO`,
   `COMFYTV_VIDEO` URL, local path, and task report.

The model's live schema validates duration, resolution, aspect ratio and reference
counts before uploads. Unsupported combinations are errors, not silent substitutions.
This first independent node exposes a common set of controls; it does not dynamically
hide incompatible choices. Cloud-side policy, size and codec constraints are still
validated by the official CLI/service.

## Recovery and spending

- One output per run. Keep Comfy's batch count at 1.
- A request is identified by canvas UUID + `request_id`, and its input fingerprint is
  persisted before submission. Same inputs/ID reuse the downloaded file or recover the
  original remote node. Changed inputs with an existing ID are rejected.
- To deliberately pay for another generation, use a **new request_id**.
- A disconnected/failed `--run` is never automatically repeated. Rerunning queries the
  existing node; if it is still running, rerun later to retrieve it. A failed remote
  task requires a new request ID for an intentional retry.
- Download failures retry only downloading, not generation.
- Comfy cancellation cannot cancel a remote LibTV job. The CLI waits for its terminal
  result; do not kill it assuming that doing so refunds/cancels the remote generation.
- Do not remove `user/daelab/libtv/jobs` while tasks may still be running. Removing
  task records removes local duplicate-charge protection.
- OS file locks prevent concurrent submission for the same request across processes.

## Files and UI reuse

- Records: `user/daelab/libtv/jobs`.
- Downloaded media: `output/daelab/libtv/<request hash>`.
- Smoke templates: `user/default/workflows/LibTV` (generated by the acceptance tool).
- Reuses Comfy's `ui.PreviewVideo` and standard widgets, and the existing DAELab
  `app_mode_bypass.js` / `app_mode_bypass_model.mjs`. No duplicate frontend controls.

## Validation

`tests/test_libtv_bridge.py` covers input constraints, ambiguous paid submissions,
concurrency locks, cache reuse and download recovery with a local synthetic fixture.
These isolated tests do **not** prove real LibTV generation.

`tools/libtv_comfy_acceptance.py --root <Comfy base> --project <UUID> --run` creates
five workflows and executes them sequentially through Comfy. It spends credits only
after preflight passes. Omit `--run` to create templates only. Live evidence is saved
to `output/daelab/libtv/acceptance/results.json`.

Initial live attempts on 2026-09-24 reached the installed node for all five models,
but failed on LibTV TLS/model-discovery errors. No successful Seedance/H3 return has
yet been verified. The separate earlier Wan result is not acceptance evidence.

There is one node identifier: DAELAB.LibTV.VideoGenerate. Select the model and all
video parameters on this node. The connection section launches official
`libtv login web --open`, probes the active account, and lists canvases with pagination.
Switching models requests live capabilities and normalizes unsupported options.
Existing loaded workflows are not silently rewritten.

Install the official CLI on each machine (PATH, ~/.libtv/libtv[.exe], or
DAELAB_LIBTV_CLI). Log in separately on every ComfyUI host; credentials stay in the
official CLI config directory and are never included in workflow serialization.
Connection management is localhost-only: the browser callback belongs to the
ComfyUI machine. It does not implement remote browser login, credential copying,
media synchronization or a distributed job lock. Do not submit the same request
concurrently from multiple machines. Network failures report unverified connection,
not an assertion that the user has logged out. No login or capability probe generates media.

After installing/updating this backend, restart ComfyUI and refresh the frontend.
The workspace repository now ships one LibTV Video.json template rather than five
model-specific templates. Historical local test workflows remain intact.
